Wireshark analiza capturas de tráfico de red (archivos `.pcap` / `.pcapng`). En CTF, los retos de red suelen esconder la flag en el contenido de los paquetes: una petición HTTP, un archivo transferido, credenciales en texto plano, datos exfiltrados por DNS, etc.

---

## PARTE 1 — Lo básico

### Identificar y abrir

```bash
file captura.pcap        # confirma que es "pcap capture file"
wireshark captura.pcap   # abrir en la GUI
```

Si no tienes GUI, `tshark` es Wireshark por línea de comandos (mismo motor, mismos filtros).

### Anatomía de la ventana

- **Panel superior**: lista de paquetes (nº, tiempo, origen, destino, protocolo, info)
- **Panel medio**: desglose del paquete seleccionado por capas (Ethernet → IP → TCP → HTTP...)
- **Panel inferior**: los bytes crudos en hex y ASCII

### El concepto clave: FILTROS

La barra de filtros (arriba, fondo verde cuando el filtro es válido) es donde vive el 90% del trabajo. Filtras para quedarte solo con lo relevante.

**No confundas dos tipos de filtro:**

- **Display filter** (el de la barra verde): filtra lo que VES, sin borrar nada.
- **Capture filter**: filtra lo que se CAPTURA. En CTF casi no lo usas porque ya te dan el pcap.

## PARTE 2 — Filtros esenciales (display filters)

### Por protocolo

```
http                 # solo HTTP
dns                  # solo DNS
tcp                  # solo TCP
ftp                  # solo FTP
telnet               # solo Telnet (credenciales en claro!)
icmp                 # pings (a veces exfiltran datos aquí)
tls                  # tráfico cifrado
smtp                 # correo
```

### Por dirección IP / puerto

```
ip.addr == 192.168.1.5           # tráfico de/hacia esa IP
ip.src == 10.0.0.1               # solo origen
ip.dst == 10.0.0.2               # solo destino
tcp.port == 80                   # puerto 80
udp.port == 53                   # DNS
```

### Por contenido (los más útiles en CTF)

```
http.request                     # solo peticiones HTTP
http.request.method == "POST"    # POSTs (login, formularios, uploads)
http.response.code == 200        # respuestas OK
frame contains "flag"            # cualquier paquete con la palabra flag
frame contains "cidsi"           # busca tu formato de flag
tcp contains "password"          # busca "password" en payload TCP
http.request.uri contains "admin"
```

### Combinar filtros

```
http and ip.src == 10.0.0.5
http.request.method == "POST" and frame contains "user"
tcp.port == 21 or tcp.port == 20    # FTP control + datos
```

Operadores: `and` `or` `not` `==` `!=` `contains` `matches` (regex).

## PARTE 3 — Técnicas para encontrar la flag

### 1. Follow Stream — el arma principal

Clic derecho en un paquete → **Follow → TCP Stream** (o HTTP/UDP Stream).

Esto reconstruye la conversación completa entre dos puntos como si fuera una charla: ves la petición y la respuesta enteras, en orden. Aquí aparecen:

- Credenciales de login en texto plano
- El contenido de páginas web
- Comandos ejecutados por telnet/FTP
- La flag transmitida

Puedes cambiar el formato del stream (ASCII, Hex Dump, Raw) en el desplegable de abajo.

### 2. Exportar objetos (archivos transferidos)

**File → Export Objects → HTTP** (o SMB, FTP-DATA, IMF).

Si por la red se transfirió un archivo (imagen, ZIP, documento), esto te lo extrae. Muchísimos retos esconden la flag en un archivo descargado que hay que sacar y luego analizar aparte (stego, binwalk, etc).

### 3. Búsqueda global de strings

**Edit → Find Packet** (Ctrl+F):

- Cambia el desplegable a **"String"** y busca en **"Packet bytes"**
- Escribe `flag`, `cidsi`, `password`, `{`

O desde consola, más rápido:

```bash
strings captura.pcap | grep -iE "flag|cidsi|password|\{"
tshark -r captura.pcap -Y "frame contains \"flag\""
```

### 4. Estadísticas para orientarte

- **Statistics → Protocol Hierarchy**: qué protocolos hay y en qué proporción. Si ves un 2% de algo raro (ICMP, DNS con payloads grandes), ahí puede estar lo oculto.
- **Statistics → Conversations**: quién habla con quién y cuánto. La conversación más grande suele tener el archivo transferido.
- **Statistics → Endpoints**: todas las IPs/puertos involucrados.

### 5. Exfiltración por canales raros

Los retos avanzados esconden datos donde no esperarías:

- **DNS**: subdominios largos y raros (`ZmxhZ3tデータ}.evil.com`) suelen ser datos codificados en base64/hex. Filtra `dns` y mira los nombres consultados.
    
    ```bash
    tshark -r cap.pcap -Y "dns" -T fields -e dns.qry.name
    ```
    
- **ICMP**: el campo de datos del ping puede llevar bytes ocultos. Filtra `icmp` y mira el payload.
- **Cabeceras HTTP raras**: `X-Flag`, cookies, User-Agents modificados.

### 6. Descifrar TLS (si te dan la clave)

Si el reto incluye un archivo de claves (`sslkeylog.txt` o una clave privada): **Edit → Preferences → Protocols → TLS → (Pre)-Master-Secret log filename** → apuntas al archivo. Wireshark descifra el HTTPS y lo puedes leer como HTTP normal.

## Cheatsheet de filtros para copiar

```
# Buscar la flag directamente
frame contains "cidsi"
frame contains "flag"
tcp contains "flag"

# Credenciales
http.request.method == "POST"
ftp.request.command == "USER" or ftp.request.command == "PASS"
telnet

# Archivos transferidos
http.request.method == "GET" and http.request.uri contains "."
ftp-data

# Exfiltración
dns.qry.name matches ".{30,}"     # nombres DNS muy largos = sospechoso
icmp

# Navegar rápido
http.request                       # todas las peticiones
http.response                      # todas las respuestas
tcp.flags.syn == 1                 # inicios de conexión
```

## PARTE 4 — tshark (línea de comandos)

Para automatizar o cuando no hay GUI:

```bash
# Listar todo el tráfico HTTP
tshark -r cap.pcap -Y "http"

# Extraer todas las URLs pedidas
tshark -r cap.pcap -Y "http.request" -T fields -e http.request.full_uri

# Extraer nombres DNS consultados
tshark -r cap.pcap -Y "dns" -T fields -e dns.qry.name

# Buscar la flag en todo el pcap
tshark -r cap.pcap -Y 'frame contains "cidsi"'

# Seguir un stream TCP concreto (el nº 5)
tshark -r cap.pcap -q -z follow,tcp,ascii,5

# Exportar credenciales detectadas
tshark -r cap.pcap -z credentials -q
```

## Flujo de trabajo recomendado en un reto de red

1. `file cap.pcap` — confirmar
2. `strings cap.pcap | grep -iE "flag|cidsi|password"` — tiro rápido
3. Abrir en Wireshark → **Statistics → Protocol Hierarchy** — ver qué hay
4. Filtrar `http` → mirar peticiones y respuestas
5. **File → Export Objects → HTTP** — sacar archivos transferidos
6. **Follow TCP Stream** en las conversaciones interesantes
7. Si nada obvio: revisar `dns` e `icmp` por exfiltración
8. Si hay TLS y te dieron claves: configurarlas y descifrar
9. Los archivos exportados → analizarlos aparte (binwalk, stego, etc.)
